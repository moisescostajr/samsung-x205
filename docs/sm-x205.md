# SM-X205 / gta8 LTE

Same Unisoc T618 (`ums512_25c10`) as the Wi-Fi SM-X200. The kernel tree we already
build for X200 contains both overlays:

| Overlay | Board | `sprd,sc-id` |
| --- | --- | --- |
| `ums512-wifionly-overlay.dts` | SM-X200 | `ums512 wifionly 1000` |
| `ums512-25c10-overlay.dts` | SM-X205 | `ums512 25c10 1000` |

Display (HX83102e), Himax touch, VBC/AW882xx audio, Mali-G52, and the SD-card
Debian ramdisk are shared. The LTE overlay adds modem AVB parts (`l_modem`,
`l_ldsp`, `l_gdsp`) and uses different reserved-memory sizes, so **do not flash
an X200 `boot.img` onto an X205**. Keep stock `dtbo` and `vbmeta` on the LTE
board, same as on Wi-Fi.

## What we reuse

- `Image-v57` (PID_NS, DRM PRIME, `CONFIG_VT`, DPU/Himax display fixes)
- The systemd ramdisk (`switch_root` onto the ext4 `gta8root` partition)
- The Debian 12 + Phosh image from the `image-latest` release
- All of `tools/gta8-bringup.sh`, GPU/Wi-Fi/audio, VLC, VNC

## What must be X205-specific

- Stock `boot.img` DT table (packed by `tools/pack-x205.py`)
- Stock `dtbo` / `vbmeta` / modem partitions — never overwrite those
- The microSD image from the release (`gta8root` + `GTA8CFG`)
- eMMC GPT: LTE adds `l_modem`/`l_ldsp`/`l_gdsp`, so `boot` is `p40`, `socko` is `p43`, `super` is `p49`. `tools/gta8-bringup.sh` resolves these by `PARTNAME`.

## Pack

The kernel and ramdisk come from the rolling release:

```sh
python3 tools/fetch-image.py --boot-pack
```

`pack-x205.py` still needs a stock X205 `boot.img` for its DT table and AVB
footer. Keep it in `stock/boot.img` or point at it explicitly:

```sh
export GTA8LTE_STOCK_BOOT=/path/to/SM-X205/boot.img
python3 tools/repack-ramdisk.py
```

Flash only the resulting `boot-pack/AP-boot-only-debug-x205-v58.tar` in Odin’s
AP slot. `repack-ramdisk.py` falls back to the release ramdisk when the local
checkout has no `tools/busybox-arm64`.

## LTE Bring-up & Cellular Data Stack

The LTE modem on the SM-X205 is the Unisoc Communication Processor (CP) accompanied by the LTE DSP (`l_ldsp`) and GSM DSP (`l_gdsp`).

### Architecture:
1. **Properties:** [`tools/propstub.c`](../tools/propstub.c) dynamically detects `SM-X205` from `/proc/cmdline` and sets `persist.vendor.sys.wifionly = "0"`, `ro.radio.noril = "no"`, and `ro.vendor.radio.modemtype = "l"`.
2. **Partitions:** [`tools/hw-up.sh`](../tools/hw-up.sh) and [`tools/lte-up.sh`](../tools/lte-up.sh) map the raw firmware partitions (`l_modem`, `l_ldsp`, `l_gdsp`, `l_agdsp`, `nvitem`, `prodnv`) into `/dev/block/by-name/`.
3. **Loader Daemon:** `/vendor/bin/modem_control` loads the baseband firmware into the CP memory and releases reset.
4. **Interfaces:** Once awake, the kernel exposes virtual serial nodes (`/dev/stty_lte*`) and pipes (`/dev/spipe_lte*`).
5. **ModemManager & Phosh:** [`tools/udev/77-unisoc-modem.rules`](../tools/udev/77-unisoc-modem.rules) tags `/dev/stty_lte*` as modem candidate ports so `ModemManager` and `NetworkManager` can manage cellular data, SIM card PIN unlock, signal strength, and APNs directly inside Phosh.

### Testing & Verification:

1. Bring up the LTE subsystem:
```sh
sh tools/lte-up.sh
```

2. Run the interactive AT command diagnostic:
```sh
python3 tools/lte-at-test.py
```
This tests `AT`, checks SIM card status (`AT+CPIN?`), signal strength (`AT+CSQ`), and operator registration (`AT+COPS?`).

3. Configure mobile broadband via NetworkManager / nmcli:
```sh
# Ensure ModemManager is running
systemctl status ModemManager || ModemManager &

# Check detected cellular devices
nmcli device

# Add mobile data connection (replace APN with your carrier, e.g. zap.vivo.com.br, claro.com.br, timbrasil.brm)
nmcli connection add type gsm con-name "LTE-Data" ifname "*" apn "your.carrier.apn"
nmcli connection up "LTE-Data"
```
